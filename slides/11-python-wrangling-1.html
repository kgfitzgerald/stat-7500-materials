Same question, two languages

From Week 4. What will this code provide us with? Say it in plain English.

hotels |>
  mutate(little_ones = children + babies) |>
  filter(little_ones >= 1, hotel == "Resort Hotel") |>

pandas

    hotels

(
    hotels_pl
    .with_columns(little_ones=pl.col("children")

            pl.col("hotel") == "Resort Hotel")

Four things to check every time you read in data:

.query(): write the condition like dplyr

(223, 32)

  • %in% works too, as in with a list (and not in):

  • Text values need the other kind of quotes: .query('hotel == "City Hotel"')

Masks or .query()? Both are fine. .query() reads better in a chain; masks work everywhere (and show up in most code online).

Why is Python wordier than dplyr?

R waits

  • filter(hotels, lead_time > 365)
  • R hands filter() the expression before running it
  • dplyr looks up lead_time inside the data
  • Called data masking

Python evaluates right away

  • lead_time > 365 runs first
  • No variable named lead_time → NameError
  • pandas never gets a chance to look in the data
  • So: hotels["lead_time"], pl.col("lead_time"), or .query()

A trade-off, not a winner:

  • Exploring data interactively: bare names read naturally (R’s strength)
  • Writing functions and code others will reuse: explicit is safer
    • Is x a column or a variable? Python never has to ask
    • R needs { } and .data$ for this (Week 9)

Chaining: Python’s pipe

A chain reads like a pipe

(
    hotels                                        # take hotels, then
    .query('hotel == "City Hotel"')               # keep City Hotel rows, then
    .sort_values("lead_time", ascending=False)    # sort by lead time, then
    [["hotel", "lead_time"]]                      # keep two columns
)
  • Each method returns a new DataFrame, and the next .method() acts on it. Like |>
  • Wrap the whole chain in parentheses so it can span lines
    • ( and ) on their own lines, one step per line in between
  • Week 10: object.verb() “reads like a pipe.” This is where it pays off

⏸ Pause & predict: no parentheses?

What happens if you leave off the outer ( )?

hotels

IndentationError / SyntaxError.

  • Without parentheses, Python thinks the statement ended after hotels

Debugging a chain: one step at a time

In R, you highlight part of a pipe and run it.

In Python, the ( ) gets in the way. Two fixes:

1. Highlight, then finish the )

  • Highlight from ( through the step you want
  • Run it (Cmd/Ctrl + Enter)
  • The Console shows ... (waiting for the ))
  • Type ) and press Enter

2. Comment out the end

(
    hotels
    .query('hotel == "City Hotel"')
    # .sort_values("lead_time", ascending=False)
    # [["hotel", "lead_time"]]
    .shape
)
(79330, 32)
  • Select lines, Cmd/Ctrl + / to comment or uncomment
  • .shape at the end is a quick row-count check
    • Did the filter keep what you expected?

This is why ( and ) go on their own lines: you can comment out any step without touching the parentheses.

  • Separate the new columns with commas, like mutate(a = ..., b = ...)

    • revenue uses total_nights, created one line earlier in the same .assign()

Style: Python’s convention (PEP 8) is no spaces around = when it names an argument (little_ones=..., ascending=False), unlike the tidyverse’s mutate(little_ones = ...). Every other = and operator still gets spaces. Either way runs; formatters like Ruff apply the convention for you.

Why the lambda? (pandas)

# Works, but refers to the ORIGINAL hotels, not the data at this step:
hotels.query("adults == 0").assign(little_ones=hotels["children"] + hotels["babies"])

# Always refers to the data flowing through the chain:
hotels.query("adults == 0").assign(little_ones=lambda d: d["children"] + d["babies"])

The first version only lines up by luck (pandas matches rows by the index).

  • If an earlier step created children, it wouldn’t exist in hotels yet
  • Habit: inside a chain, use lambda d:

pandas 3 adds a shortcut: .assign(little_ones=pd.col("children") + pd.col("babies")). Very dplyr-like. It’s new, so most code you find online uses lambda.

True

Subsets make a new object (pandas 3)

city = hotels[hotels["hotel"] == "City Hotel"]
city["adr"] = 0        # change the subset
hotels["adr"].max()    # hotels: untouched
np.float64(5400.0)
  • = just names the new DataFrame the filter made
  • Same for selected columns, .loc/.iloc, and method results

= always works the same way: it puts a name on an object.

  • What matters is whether the right side makes a new object
    • Filters, subsets, and methods do
  • pandas 3: changing a subset never changes the original, like R’s copy-on-modify

Why “Copy-on-Write”?

  • Filtering or selecting doesn’t copy the data right away
    • That would be slow for big tables
  • The new object shares memory with the original…
  • …until one of them is written to (changed). Then pandas makes the copy
  • So: copy on write
    • Separate objects, without paying for copies you never use

R does this too, and calls it copy-on-modify

  • In R, it applies to everything, even b <- a
    • b[1] <- 0 copies first, so a never changes
  • In pandas 3, it applies to derived objects only
    • h2 = hotels is still one object with two names (Week 10’s sticky notes)

⏸ Pause & predict: chained assignment

You want to set adr to 0 for canceled bookings. Does this work?

hotels[hotels["is_canceled"] == 1]["adr"] = 0

No. In pandas 3 it never changes hotels.

  • You get a ChainedAssignmentError warning, and nothing else happens

One step with .loc (changes hotels)

hotels.loc[hotels["is_canceled"] == 1, "adr"] = 0

Or a new column in a chain

hotels.assign(
    adr_kept=lambda d:
        np.where(d["is_canceled"] == 1, 0, d["adr"]))

Old StackOverflow answers are full of the first version. Check the pandas version!

Tonight’s gotchas

  1. df["x"] is a Series; df[["x"]] is a DataFrame
  2. Combine conditions with & / | / ~ and parentheses, not and / or / not

No Index, no Copy-on-Write trap

  • No Index, no .loc, no .iloc
    • Rows are positions only (hotels_pl.row(0), hotels_pl[0:3])
    • After sorting, the first row is simply the first row
    • You still need to read .loc/.iloc: they’re in almost every pandas example online
  • polars never changes a DataFrame in place, so chained assignment can’t happen
    • Changing values is always a new column (like if_else() in dplyr):

                                  .then(pl.col("adr"))

polars gotchas

  1. Tell read_csv() what missing looks like (null_values=); only empty cells count by default
  2. Columns inside verbs are pl.col("x")
  3. Sorting puts missing values first unless nulls_last=True
  4. New columns in one .with_columns() can’t use each other: chain a second one
  5. value_counts() returns a DataFrame, is unsorted unless sort=True, and counts missing values
  6. .mean() skips missing values (like pandas)

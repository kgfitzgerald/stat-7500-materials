Don’t repeat yourself

A familiar request

Your manager wants monthly sales, dollar volume, and median price for Texas cities, standardized so they can share one chart.

tx_std <- txhousing |>
  mutate(
    sales  = (sales - mean(sales, na.rm = TRUE)) /
      sd(sales, na.rm = TRUE),
    volume = (volume - mean(volume, na.rm = TRUE)) /
      sd(sales, na.rm = TRUE),
    median = (median - mean(median, na.rm = TRUE)) /
      sd(median, na.rm = TRUE)
  )

This code runs without an error or warning. Is it correct?

Copy, paste, … bug

    volume = (volume - mean(volume, na.rm = TRUE)) /
      sd(sales, na.rm = TRUE),
  • One edited line was missed while copying and pasting.
  • R cannot catch it: dividing by the wrong standard deviation is valid code.
  • The more copies you make, the more places a mistake can hide.

Rule of thumb: once you have copied a block of code twice, write a function.

Functions

Anatomy of a function

standardize <- function(x) {
  (x - mean(x, na.rm = TRUE)) / sd(x, na.rm = TRUE)
}
  • Name: standardize. Use a verb that says what it does.
  • Arguments: x. These are the inputs that change from use to use.
  • Body: the code inside { }.
  • The last value computed is returned.

Test it where you know the answer

standardize(c(1, 2, 3, 4, 5))
[1] -1.2649111 -0.6324555  0.0000000  0.6324555  1.2649111
standardize(c(10, 20, NA, 40))
[1] -0.8728716 -0.2182179         NA  1.0910895

Before trusting a function on 8,000 rows, check it on 5 values you can verify by hand.

  • Is the middle value 0?
  • Did the NA stay NA, without breaking the other values?

Arguments with defaults

Flag unusual values with the 1.5 × IQR rule (the boxplot rule):

is_outlier <- function(x, k = 1.5) {
  q <- quantile(x, c(0.25, 0.75), na.rm = TRUE)
  iqr <- q[2] - q[1]
  x < q[1] - k * iqr | x > q[2] + k * iqr
}
diamonds |>
  summarise(
    n_mild    = sum(is_outlier(price)),          # uses k = 1.5
    n_extreme = sum(is_outlier(price, k = 3))    # overrides default
  )
# A tibble: 1 × 2
  n_mild n_extreme
   <int>     <int>
1   3540       120

Fail loudly: check your inputs

Remember number_of_cats, stored as character? Make your function refuse bad input.

standardize <- function(x) {
  if (!is.numeric(x)) {
    stop("`x` must be numeric, not ", class(x)[1], ".")
  }
  (x - mean(x, na.rm = TRUE)) / sd(x, na.rm = TRUE)
}

standardize(c("1", "2", "two"))
Error in `standardize()`:
! `x` must be numeric, not character.

A clear error now is better than a quiet NA three steps later.

Functions that use column names

Suppose you often compute a grouped mean. A first attempt:

group_mean <- function(df, group_var, var) {
  df |>
    group_by(group_var) |>
    summarise(mean = mean(var, na.rm = TRUE))
}

group_mean(mpg, class, hwy)
Error in `group_by()`:
! Must group by variables found in `.data`.
✖ Column `group_var` is not found.

group_by() looks for a column literally named group_var.

Embrace with {{ }}

Wrapping an argument in {{ }} tells tidyverse functions to use the column the user supplied.

group_mean <- function(df, group_var, var) {
  df |>
    group_by({{ group_var }}) |>
    summarise(mean = mean({{ var }}, na.rm = TRUE), n = n())
}

The same idea works for plots

hist_of <- function(df, var, binwidth = NULL) {
  ggplot(df, aes(x = {{ var }})) +
    geom_histogram(binwidth = binwidth, color = "white")
}

When is a function worth it?

  • You have copied a block of code two or more times.
  • A rule needs to be applied consistently, such as an outlier, a cleaning, or a fiscal-year rule.
  • You want to name a step so the pipeline reads like a description.

Keep functions small: one job, a clear name, and tested on a tiny example.

map(): the loop, packaged

The purrr package (part of the tidyverse) replaces the loop bookkeeping with one function:

tx_list <- map(files, read_csv)

map(.x, .f) applies .f to each element of .x and returns a list:

map(c(a, b, c), f)   # gives   list(f(a), f(b), f(c))

No container to set up and no index i to keep track of.

Read and stack in one pipeline

tx_all <- files |>
  map(read_csv) |>       # read each file into a list
  bind_rows()            # stack them into one data frame

tx_all |> count(year)
# A tibble: 4 × 2
   year     n
  <dbl> <int>
1  2012   552
2  2013   552
3  2014   552
4  2015   322

When the 2016 file arrives, this code doesn’t change: list.files() picks it up automatically.

Shortcuts and generalizations

For CSVs with the same columns, readr can read and stack them in one step:

read_csv(files)

The map() pattern works for anything. For example, every sheet in an Excel workbook:

path   <- "data/regional-budgets.xlsx"
sheets <- readxl::excel_sheets(path)     # "East" "North" "South" ...

budgets <- sheets |>
  map(\(s) readxl::read_excel(path, sheet = s)) |> #\(s) is shortcut for function(s)
  bind_rows()

Older course materials and many colleagues use the apply family. They do the same jobs.

Scenario: one plot per city

First, a function that makes one plot:

city_plot <- function(city_name) {
  txhousing |>
    filter(city == city_name) |>
    ggplot(aes(x = date, y = median)) +
    geom_line() +
    scale_y_continuous(labels = label_dollar()) +
    labs(title = city_name, x = NULL, y = "Median sale price")
}
city_plot("Austin")

Then iterate: save them all

cities <- c("Austin", "Dallas", "Houston", "San Antonio")

walk(cities,                                   # for each city in cities...
  \(city) ggsave(                              # ...given one city name, save a plot:
    filename = paste0("img/median-price-", city, ".png"),  # e.g. "img/median-price-Austin.png"
    plot     = city_plot(city),                # the plot for that city
    width = 6, height = 4                      # size in inches
  ))
  • walk() is map() for side effects: we want the files, not a returned value.
  • Next quarter’s update means re-running a few lines, not editing 4 (or 40) copies.
for (i in 1:length(cities)) {
  ggsave(
    filename = paste0("img/median-price-", cities[i], ".png"),
    plot     = city_plot(cities[i]),
    width = 6, height = 4
  )
}

Distributions

Four functions for every distribution

Prefix Gives you Workplace question
p P(X ≤ x) “What fraction of deliveries take over 4.5 days?”
q the value with a given probability below it “What delivery time can we promise 95% of customers?”
d density, or P(X = x) for counts “What’s the chance of exactly 2 no-shows?”
r random draws “Give me 1,000 fake delivery times”

Suffixes: norm, binom, pois, unif, exp, t, …

Simulation

Why simulate?

Sometimes the math is hard, or its assumptions don’t match reality. Instead:

  1. Write a function that runs the random process once
  2. Repeat it many times: replicate() or map()
  3. Summarize the results: a proportion, mean, or plot

This uses all three ideas from today: functions, sampling, and iteration.

Scenario: overbooking

A flight has 100 seats. Historically 95% of ticketed passengers show up. The airline sells 105 tickets. How often does someone get bumped?

Step 1: one flight as a function

one_flight <- function(tickets = 105, seats = 100, p_show = 0.95) {
  showed_up <- rbinom(1, size = tickets, prob = p_show)
  showed_up > seats          # TRUE if someone is bumped
}

one_flight()
[1] TRUE

Steps 2 and 3: repeat and summarize

set.seed(7500)
bumped <- replicate(10000, one_flight())
mean(bumped)
[1] 0.3911

Here the math is available, so we can check it:

pbinom(100, size = 105, prob = 0.95, lower.tail = FALSE)
[1] 0.3924337

The simulation agrees with the exact answer. Now we can trust it on harder versions.

How many tickets should we sell?

  • Plot
  • Code
set.seed(7500)
tibble(tickets = 100:110) |>
  mutate(p_bump = map_dbl(tickets,
           \(t) mean(replicate(10000, one_flight(tickets = t))))) |>
  ggplot(aes(x = tickets, y = p_bump)) +
  geom_line() +
  geom_point() +
  geom_hline(yintercept = 0.05, linetype = "dashed") +

Where simulation shines: reality is messier

On holiday flights (20% of flights), nearly everyone shows up. On other flights, fewer do. The average show rate is still 95%.

one_flight_v2 <- function(tickets = 105, seats = 100) {
  holiday   <- runif(1) < 0.20
  p_show    <- if_else(holiday, 0.99, 0.94)
  showed_up <- rbinom(1, size = tickets, prob = p_show)
  showed_up > seats
}

Scenario: can I trust my confidence interval?

Customer purchase amounts are right-skewed: most are small and a few are large. You have n = 20 purchases and report t.test(x)$conf.int.

Does a “95%” interval really capture the true mean 95% of the time?

Simulate the method, not just the data

true_mean <- exp(3 + 1.2^2 / 2)    # mean of this lognormal population

ci_covers <- function(n) {
  x  <- rlnorm(n, meanlog = 3, sdlog = 1.2)   # one sample of size n
  ci <- t.test(x)$conf.int                    # the method we'd use
  ci[1] <= true_mean & true_mean <= ci[2]     # did it work?
}

set.seed(7500)
mean(replicate(10000, ci_covers(n = 20)))
[1] 0.8338

Bootstrap

A question without a formula

You audited a random sample of 150 sales and need to report the median price, with a margin of error.

  • t.test() gives intervals for means, assuming the conditions hold.
  • There is no simple textbook formula for the uncertainty of a median, or a 90th percentile, or a ratio…

Bootstrap idea: your sample is the best picture of the population you have. Resample from it, with replacement, recompute the statistic, and repeat. The spread of those results estimates the sampling variability.

Bootstrap in four lines

set.seed(7500)
audit <- diamonds |> slice_sample(n = 150)        # the sample we have

one_boot <- function(x) median(sample(x, replace = TRUE))
boot_medians <- replicate(5000, one_boot(audit$price))

quantile(boot_medians, c(0.025, 0.975))           # 95% percentile interval
  2.5%  97.5% 
1441.5 2763.0

Same recipe as before: a function for one resample, repeated, then summarized.

Look at the bootstrap distribution

ci <- quantile(boot_medians, c(0.025, 0.975))

ggplot(tibble(median = boot_medians), aes(x = median)) +
  geom_histogram(bins = 30, color = "white") +
  geom_vline(xintercept = ci, color = "#E9AFA3", linewidth = 1) +
  scale_x_continuous(labels = label_dollar())

Here we have the full diamonds data. Does the interval capture median(diamonds$price)?

Any statistic, same recipe

Change one line to bootstrap a different statistic:

# 90th percentile price
one_boot <- function(x) quantile(sample(x, replace = TRUE), 0.9)

Cautions

  • The bootstrap can’t fix a biased sample; it only measures random variability.
  • It works poorly for extremes like the max, and for very small samples.
  • For full-featured bootstrap methods, see the boot or infer packages.

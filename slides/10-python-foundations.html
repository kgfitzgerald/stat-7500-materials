Functions vs. methods

R mostly uses functions: verb(object). Python uses both functions and methods: object.verb().

word = "villanova"
len(word)          # function: verb(object)
9
word.upper()       # method: object.verb()
'VILLANOVA'

Read object.verb() like a pipe: take word, then make it uppercase. That’s exactly how pandas chains will read next week.

Slicing: start is in, stop is out

x[start:stop] takes elements from start up to but not including stop.

x = [10, 20, 30, 40, 50]
x[1:3]
[20, 30]

Think of the slice numbers as fence posts between elements:

0 1 2 3 4 5
10 20 30 40 50

x[1:3] takes everything between post 1 and post 3: [20, 30]. And x[a:b] always has b - a elements.

Slicing shortcuts

x = [10, 20, 30, 40, 50]
x[:2]      # first 2
[10, 20]
x[2:]      # everything from index 2 on
[30, 40, 50]
x[-2:]     # last 2
[40, 50]

Slicing with a step (good to know)

The core you’ll use constantly: x[0], x[-1], x[:n], x[-n:]. This slide is a bonus.

The full form is x[start:stop:step]. Leave any part blank to use its default (beginning, end, step of 1).

x[::2]      # every 2nd element, starting at index 0
[10, 30, 50]
x[1::2]     # every 2nd element, starting at index 1
[20, 40]
x[::-1]     # step of -1: reversed
[50, 40, 30, 20, 10]

R equivalent of x[1::2]: x[seq(2, length(x), by = 2)]

Names and mutability

⏸ Pause & predict: the most important slide today

What does print(a) show?

a = [1, 2, 3]
b = a
b.append(4)
print(a)
[1, 2, 3, 4]

In R, b <- a makes (effectively) a copy, so changing b leaves a alone. In Python, b = a makes a second name for the same object.

Names are sticky notes

ab
→ [1, 2, 3, 4]
  • b = a sticks a second note on the same list
  • b.append(4) changes the list itself (it mutates it), so both names see the change
  • R’s model is “copy-on-modify”: modifying b quietly creates a new copy for b

If you want a copy, ask for one

a = [1, 2, 3]
b = a.copy()       # or list(a)
b.append(4)
print(a, b)
[1, 2, 3] [1, 2, 3, 4]
a is b             # same object?
False

Not everything can be mutated

Numbers and strings are immutable. You can’t change them, only move the sticky note to a new value.

x = 5
y = x
y = y + 1          # makes a NEW number and moves the "y" note to it
print(x, y)
5 6
Mutable (can change in place) Immutable
list, dict, NumPy array, DataFrame int, float, str, bool

Why this matters: functions

def add_total(values):
    values.append(sum(values))
    return values

sales = [10, 20, 30]
with_total = add_total(sales)
sales
[10, 20, 30, 60]

The function quietly changed sales. An R function would have worked on a copy.

Arrays have one type

Like R vectors, an array holds one type. Mix types and NumPy converts everything:

np.array([1, 2, "three"])
array(['1', '2', 'three'], dtype='<U21')

Like c(1, 2, "three") in R: now everything is a string.

⏸ Pause & predict: will mass.std() match R’s sd(mass)?

print(mass.std(), mass.std(ddof=1))
459.563901532569 496.3857466968704

NumPy’s default divides by \(n\). R’s sd() divides by \(n-1\). For a sample SD, use ddof=1. (pandas uses \(n-1\) by default. Yes, it’s inconsistent.)

ddof = “delta degrees of freedom”: NumPy divides by \(n - \text{ddof}\). So ddof=0 → \(n\), ddof=1 → \(n - 1\).

Demo 3: standardize(), again

Practice file, Demo 3. Week 9’s function, in Python:

R

standardize <- function(x) {
  (x - mean(x, na.rm = TRUE)) /
    sd(x, na.rm = TRUE)
}

Python

def standardize(x):
    x = np.asarray(x, dtype=float)
    return (x - np.nanmean(x)) / np.nanstd(x, ddof=1)
standardize([1, 2, 3, 4, 5])
array([-1.26491106, -0.63245553,  0.        ,  0.63245553,  1.26491106])

Functions, loops, and comprehensions

Anatomy of a function

def prop_missing(x, digits=2):
    """Proportion of values in x that are missing (nan)."""
    x = np.asarray(x, dtype=float)
    return float(round(np.isnan(x).mean(), digits))
  • def name (arguments): then an indented body. Indentation is the syntax (R uses { })
  • digits=2 is a default, just like R
  • The """docstring""" documents it: try help(prop_missing)
  • return is required. Python does not return the last value automatically

Your turn: write a function

Pause the video. Practice file, Your turn 3 (about 5 minutes).

Write summarize_num(x) that returns a dict with the number of values n, number missing n_missing, the mean, and the sample sd (ignoring missing values).

Test it on [2, 4, 4, 4, 5, 5, 7, 9]. You should get a mean of 5 and an SD of about 2.14.

Stretch: raise a ValueError if there are fewer than 2 non-missing values. Experienced: use a dict comprehension to apply it to every column of tx.

Your turn 3: one solution

def summarize_num(x):
    """n, number missing, mean, and sample SD of x."""
    x = np.asarray(x, dtype=float)
    n_missing = int(np.isnan(x).sum())
    if len(x) - n_missing < 2:
        raise ValueError("Need at least 2 non-missing values.")
    return {"n": len(x), "n_missing": n_missing,
            "mean": float(np.nanmean(x)), "sd": float(np.nanstd(x, ddof=1))}

Randomness and simulation

Random numbers: make a generator

R uses a global seed. Modern NumPy uses a random number generator object that you create with a seed:

R

set.seed(7500)
sample(1:100, 3)

Python

rng = np.random.default_rng(7500)
rng.choice(np.arange(1, 101), 3, replace=False)
array([67, 80, 31])
  • Then draw from it with methods: rng.choice(), rng.normal(), …
  • Same seed → same numbers in Python, but not the same numbers as R (different generators)
  • Older tutorials use np.random.seed(). That still works but is the legacy approach

sample() in Python

rng = np.random.default_rng(7500)
reviewers = ["Ana", "Ben", "Cal", "Dee", "Eli", "Fay"]
rng.choice(reviewers, 2, replace=False)        # pick 2, no repeats
array(['Dee', 'Ben'], dtype='<U3')
rng.permutation(reviewers)                      # random order
array(['Cal', 'Fay', 'Dee', 'Eli', 'Ana', 'Ben'], dtype='<U3')
rng.choice(["bronze", "silver", "gold"], size=8, p=[0.6, 0.3, 0.1])
array(['bronze', 'bronze', 'bronze', 'silver', 'gold', 'bronze', 'bronze',
       'gold'], dtype='<U6')

Gotcha: R’s sample() defaults to without replacement. rng.choice() defaults to with replacement. Always write replace= explicitly.

Demo 5: the overbooked flight

Practice file, Demo 5. Week 9’s simulation, in Python. 100 seats, 105 tickets sold, each passenger shows up with probability 0.95. How often is someone bumped?

rng = np.random.default_rng(7500)

def one_flight(tickets=105, seats=100, p_show=0.95):
    showed_up = rng.binomial(tickets, p_show)
    return showed_up > seats          # True if someone is bumped

bumped = [one_flight() for _ in range(10_000)]   # R: replicate(10000, one_flight())
np.mean(bumped)
np.float64(0.3932)

About 0.39, same as our R simulation in Week 9. Same three steps: a function for one run → repeat it → summarize.

_ is the conventional name for a loop variable you don’t use. 10_000 is just 10000, easier to read.

Today’s gotchas

  1. Counting starts at 0, and slices exclude the stop value
  2. Powers are **, not ^
  3. b = a doesn’t copy a list, dict, or array. Use .copy()
  4. Lists aren’t vectors: use NumPy arrays for math
  5. np.std() divides by \(n\); use ddof=1 for a sample SD
  6. Functions need an explicit return
  7. rng.choice() samples with replacement unless told otherwise
  8. Indentation is part of the syntax

Every one of these runs (or fails) differently than you’d expect from R. When something looks off, check this list first.

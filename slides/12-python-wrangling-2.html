Best practice: flat by default

Keep information in columns. After every groupby:

  • use as_index=False up front, or
  • .reset_index() at the end

.merge(), .query(), plotnine, and CSV files all expect columns.

The Index is useful on purpose for time series and lookups by name. But if you get weird NaNs after arithmetic, or .loc returns the wrong row, check the Index first.

group_by() + mutate() is transform()

  • .agg() collapses each group to one row
  • .transform() keeps every row

R

penguins <- penguins |>
  group_by(species) |>
  mutate(species_mean =
           mean(body_mass_g,
                na.rm = TRUE)) |>
  ungroup()

Python

penguins["species_mean"] = (
    penguins
    .groupby("species")["body_mass_g"]
    .transform("mean")
)
penguins[["species", "species_mean"]].head(3)
species species_mean
0 Adelie 3700.662252
1 Adelie 3700.662252
2 Adelie 3700.662252

.transform() returns one value per row.

  • Same length in, same length out
  • This adds the column to penguins, like penguins <- ... in R

transform() in a chain

A grouped object has no .assign(), so in a chain, groupby goes inside the lambda:

(
    penguins
    .assign(species_mean=lambda d:
            d.groupby("species")["body_mass_g"].transform("mean"))
    [["species", "body_mass_g", "species_mean"]]
    .head(3)
)
species body_mass_g species_mean
0 Adelie 3750.0 3700.662252
1 Adelie 3800.0 3700.662252
2 Adelie 3250.0 3700.662252

Read the lambda as a sentence:

  • “For the data at this step, group by species, take body mass, and give every row its species’ mean.”

Same result, but penguins itself doesn’t change.

  • Like penguins |> mutate(...) without <-

Joins

Same joins, new name: merge()

Demo 2 in Positron

purchases = pd.DataFrame({
    "customer_id": [1, 1, 1, 2, 2, 2],
    "item": ["bread", "milk", "banana", "milk", "banana", "toilet paper"]})
prices = pd.DataFrame({
    "item": ["avocado", "banana", "bread", "milk", "toilet paper"],
    "price": [0.50, 0.15, 1.00, 0.80, 3.00]})

R

purchases |>
  left_join(prices, by = "item") |>
  group_by(customer_id) |>
  summarize(revenue = sum(price))

Python

(
    purchases
    .merge(prices, on="item", how="left")
    .groupby("customer_id", as_index=False)
    .agg(revenue=("price", "sum"))
)
customer_id revenue
0 1 1.95
1 2 3.95

Take purchases, then look up each price, then group by customer, then add up.

The how= argument

dplyr pandas Keeps
left_join(x, y) x.merge(y, how="left") all rows of x
right_join(x, y) x.merge(y, how="right") all rows of y
inner_join(x, y) x.merge(y, how="inner") rows with a match in both
full_join(x, y) x.merge(y, how="outer") all rows of both

Key columns with different names? R: join_by(item == product)

x.merge(y, left_on="item", right_on="product", how="left")

Always write how=. The default is "inner", which quietly drops unmatched rows. In R, the join’s name is the choice; pandas lets you forget.

Anti- and semi-joins

Enrolled, no survey (R: anti_join(enrolment, survey))

(
    enrolment
    .merge(survey[["id"]], on="id",
           how="left", indicator=True)
    .query("_merge == 'left_only'")
    .drop(columns="_merge")
)
id name
0 1 Dave Friday 
enrolment[~enrolment["id"].isin(survey["id"])]
id name
0 1 Dave Friday
  • survey[["id"]] merges only the key, so survey’s other columns don’t come along (like R)

Enrolled, with survey (R: semi_join(enrolment, survey))

enrolment.merge(
    survey[["id"]].drop_duplicates(),
    on="id", how="inner"

1 3 Sura Selambarom 
enrolment[enrolment["id"].isin(survey["id"])]
id name
1 2 Hermine

  • .drop_duplicates(): if an id appeared twice in survey, the inner merge would repeat that row

⏸ Join detective: predict the rows

A has 100 rows and a unique id. In B:

  • 90 of A’s ids appear once
  • 5 appear twice
  • 5 don’t appear at all

How many rows in A.merge(B, on="id", how="left")?

\[90 \times 1 + 5 \times 2 + 5 \times 1 = 105\]

  • Duplicate keys multiply rows; no match is kept once, with NaN
  • Same as left_join() in R
  • Predict the row count before every join, then check it

Tonight’s gotchas

  1. groupby() puts the groups in the Index
    • Use as_index=False or .reset_index()
  2. groupby() drops missing group labels unless dropna=False
  3. "size" counts rows; "count" counts non-missing values
  4. agg collapses (summarize); transform keeps every row (mutate)
  5. merge() defaults to an inner join: always write how=
  6. Duplicate keys multiply rows: predict, then check, or use validate=
  7. pivot() errors on duplicates: summarize first, or use pivot_table()
